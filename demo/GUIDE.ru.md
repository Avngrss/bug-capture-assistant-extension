# Corner Shop: как работать с багами

Corner Shop — учебный магазин с заложенными багами. Ни один из них не бросается в глаза: человек его пропустит, забудет или опишет неверно. На них видно, что даёт Bug Capture Assistant.

## Что ловит расширение

Расширение не ищет баги вместо тестировщика. Оно записывает технические следы, которые оставляет браузер, и привязывает их к шагам, которые к ним привели.

| Ловит | Как это выглядит |
| --- | --- |
| Упавший запрос | Ответ 4xx или 5xx, обрыв соединения |
| Ошибку внутри ответа 200 | JSON-ответ с `"success": false`, `"ok": false`, непустым `"error"` или `"errors"` (как в GraphQL) |
| Ошибку JavaScript | `console.error`, необработанное исключение, необработанный промис |
| Видимую ошибку на странице | Элемент по правилам: `role="alert"`, `aria-invalid="true"`, `data-testid`/`data-qa="error-message"`, свои CSS-селекторы из Settings |

Не ловит ошибки логики без следа: неверную цену при ответе 200, кривую вёрстку, не тот текст. В этом магазине у каждого бага есть след, и именно он попадает в карточку.

Ошибки на одной странице, случившиеся в пределах 3 секунд, расширение склеивает в одну карточку. Скриншот по умолчанию снимается только для ошибок на странице. Для сетевых и консольных ошибок его можно включить в Settings.

## Подготовка

1. Установи расширение 0.3.0 из `releases/bug-capture-assistant-0.3.0-chrome.zip`:
   - распакуй архив в отдельную папку;
   - в Chrome открой `chrome://extensions`, включи Developer mode;
   - нажми Load unpacked и выбери папку, в которой лежит `manifest.json`.
2. Запусти магазин из корня репозитория: `node demo/serve.mjs`. Открой `http://localhost:4173/sign-in/`. Окно терминала не закрывай.
3. Внизу страницы нажми **Reset demo**: корзина и вход хранятся в браузере, сброс убирает остатки прошлого прогона.
4. Войди: любой email, пароль `demo1234`. Откроется каталог.
5. Открой боковую панель расширения → **Start capture** → дождись **Capturing this tab**.

Правила прогона:

- Между багами на одной странице жди не меньше 3 секунд, иначе они попадут в одну карточку.
- Поиск запускай кнопкой **Search**, а не Enter. Тогда в шагах будет `Click “Search”`.
- Промокод вводи без опечаток: неверный код подсвечивает поле, и появится лишняя карточка.
- Кружку *Ceramic Mug* добавляй в корзину один раз: на ней построен баг 3.

Для самопроверки следи за счётчиком **Potential issues** в панели. Он считает следы, а не карточки:

| После | Счётчик |
| --- | --- |
| Бага 1 | Network 1 |
| Бага 2 | Network 2 |
| Бага 3 | UI 1 · Network 3 |
| Бага 4 | UI 1 · Console 1 · Network 3 |
| Бонуса | UI 2 · Console 1 · Network 3 |
| Бага 5 | UI 2 · Console 1 · Network 4 |
| Бага 6 | UI 2 · Console 1 · Network 5 |

## Баг 1. Поиск «ничего не нашёл», а на самом деле упал

**Как воспроизвести** (страница Shop)

1. В поле поиска введи `men's watch` → нажми **Search**. Будет «No products match “men's watch”.»
2. Для контраста введи `watch` → **Search**: часы находятся.
3. Сотри текст в поле: вернутся все товары.

Сломает поиск любой запрос с апострофом, например `kid's`.

**Что сломано.** Сервер вставляет запрос в SQL без экранирования и на апострофе падает с ответом 500 (`sw.js`, поиск по `PLANTED BUG`). Страница любой неуспешный ответ показывает как пустой результат (`assets/pages/shop.js`).

**Что видит человек.** Обычное «ничего не найдено».

**Что ловит расширение.** Упавший запрос. Карточка: `[Shop] /api/products?q=men's watch fails with HTTP 500`, шаги — ввод запроса и `Click “Search”`.

**Почему это помогает.** Симптом выглядит как нормальный ответ. Без расширения баг либо не заведут, либо заведут неверно: «поиск не находит часы». Карточка сразу говорит, что упал сервер и на каком запросе.

## Баг 2. Товар «добавлен», а в корзине его нет

**Как воспроизвести** (Shop → Cart)

1. Подожди 3 секунды после бага 1. Нажми **Add to cart** у *Wireless Headphones* (−30%). Появится «Wireless Headphones added to your cart.», счётчик корзины +1.
2. Добавь *Ceramic Mug*, один раз. Можно добавить ещё что-нибудь.
3. Нажми **Cart** в шапке. Наушников нет, счётчик показывает столько, сколько товаров в списке.

**Что сломано.** Каталог работает оптимистично: счётчик и «добавлено» показываются сразу, до ответа сервера. Сервер на наушники отвечает 500 «Discount rule SALE-30 not found». Страница ошибку игнорирует: ни сообщения, ни отката (`assets/pages/shop.js`). Корзина при открытии подгоняет счётчик под сохранённые товары, и последняя улика пропадает (`assets/pages/cart.js`).

**Что видит человек.** Всё добавилось. Через несколько экранов в корзине не хватает товара.

**Что ловит расширение.** Упавший запрос в момент клика. Карточка: `[Shop] /api/cart/items fails with HTTP 500`, описание «After clicking “Add to cart: Wireless Headphones” on Shop…».

**Почему это помогает.** Симптом и причина на разных экранах. Без расширения тикет звучал бы как «корзина теряет товары», без шагов и момента. Карточка указывает на тот самый клик, хотя заметил ты всё позже.

## Баг 3. Ошибка мелькнула на секунду

**Как воспроизвести** (страница Cart)

1. У *Ceramic Mug* нажми **+**: станет 2, всё хорошо.
2. Нажми **+** ещё раз: станет 3. Справа внизу примерно на 1,2 секунды мелькнёт красный тост «Couldn't update the quantity.»
3. Количество осталось 3, сумма посчитана за три.

**Что сломано.** На складе 2 кружки. Сервер честно отвечает 409 `insufficient_stock`. Ошибка на странице: она сначала показывает новое количество, потом на долю секунды показывает невнятное сообщение и количество не откатывает (`assets/pages/cart.js`).

**Что видит человек.** «Что-то красное мигнуло». Прочитать и заскриншотить не успеть.

**Что ловит расширение.** Видимую ошибку и запрос вместе. Карточка: `[Cart] Couldn't update the quantity.`, в описании «PATCH /api/cart/items fails with HTTP 409», шаг `Click “Increase quantity: Ceramic Mug”`. Есть скриншот, снятый, пока тост был на экране.

**Почему это помогает.** Текст, ответ сервера и скриншот мимолётной ошибки сохранены. Без них остаётся «что-то мигнуло, не знаю что».

## Баг 4. Промокод срабатывает только со второго раза

**Как воспроизвести** (страница Cart)

1. Подожди 3 секунды после бага 3. Введи `WELCOME10` → **Apply**. Ничего не происходит.
2. Нажми **Apply** ещё раз. Появится «WELCOME10 applied: −10%…», в итогах строка Discount.

**Что сломано.** Для скидки код загружает сумму корзины, но разработчик забыл дождаться загрузки (пропущен `await`, `assets/pages/cart.js`):

- первый клик: данных ещё нет, код падает с `TypeError: Cannot read properties of undefined (reading 'subtotal')`;
- в фоне: загрузка завершается, данные запоминаются;
- второй клик: данные уже есть, скидка применяется;
- новый заход в корзину: память очищена, у каждого покупателя первый клик снова проваливается.

**Что видит человек.** «Подвисло, со второго раза сработало». Ни сетевой ошибки, ни сообщения на странице.

**Что ловит расширение.** Ошибку JavaScript. Карточка: `[Cart] Cannot read properties of undefined (reading 'subtotal')`, шаги ведут к `Click “Apply”`.

**Почему это помогает.** Единственный след — строка в консоли. Если консоль не была открыта в эту секунду, бага как будто не было. А его видит каждый покупатель, и часть из них решит, что код не работает.

## Баг 5. «Заказ оформлен», а заказа нет

**Как воспроизвести** (страница Checkout)

1. В корзине нажми **Proceed to checkout**. Доставка Standard выбрана по умолчанию.
2. Нажми **Place order**. Примерно секунду видно «Placing your order…», потом «Thank you! Your order is placed.»

**Что сломано.** Сервер на любой заказ отвечает 500 `payment_gateway_timeout`. Страница статус не проверяет и всё равно ведёт на страницу успеха (`assets/pages/checkout.js`).

**Что видит человек.** Успех. Фронт работает дальше, как будто всё в порядке.

**Что ловит расширение.** Упавший запрос. Карточка: `[Checkout] /api/orders fails with HTTP 500`, описание «After clicking “Place order” on Checkout…».

**Почему это помогает.** Самый дорогой тип: покупатель и тестировщик видят успех. В DevTools вкладка Network при переходе на другую страницу очищается, если не включён Preserve log, и ответ 500 пропадает. Расширение его сохраняет.

## Баг 6. «Вы подписаны», а письма не будет

**Как воспроизвести** (страница Order placed, сразу после бага 5)

1. Подожди 3 секунды. В блоке «Get 10% off your next order» email уже подставлен из входа.
2. Нажми **Subscribe**. Через полсекунды появится «You're subscribed! Your 10% code is on its way.»

**Что сломано.** Почтовый сервис лежит. Сервер отвечает 200, а ошибку кладёт в тело: `{"success": false, "error": "Mail service unavailable"}` (`sw.js`). Страница смотрит только на код ответа и сообщает об успехе (`assets/pages/order-confirmation.js`).

**Что видит человек.** Успех. В DevTools на вкладке Network тоже всё зелёное: `200 OK`. Ошибку видно, только если открыть сам ответ и прочитать его.

**Что ловит расширение.** Ошибку внутри успешного ответа. Карточка: `[Order placed] Mail service unavailable`, в описании «After clicking “Subscribe” on Order placed, the POST request to /api/newsletter returns HTTP 200, but the response reports an error…».

**Почему это помогает.** Такой баг не видно ни на странице, ни по статусам в Network. Так устроены многие API: GraphQL почти всегда отвечает 200 и кладёт ошибки в `errors`, у Slack и похожих API в ответе 200 бывает `"ok": false`. Расширение читает небольшие JSON-ответы (до 256 КБ) и ищет типовые признаки ошибки на верхнем уровне ответа. В карточку попадает только текст ошибки, а не весь ответ. Если на проекте эти поля значат что-то другое, нажми Exclude или выключи проверку в Settings → Capture.

## Бонус. Ошибка в стиле проекта: научить расширение одним правилом

Это UI-баг, но показывает он другое: настройку расширения под конкретный проект.

**Как воспроизвести** (страница Checkout, до бага 5)

1. Выбери **Express courier**. Появится красный баннер «Delivery unavailable…». Счётчик в панели не изменится: расширение ошибку не увидело.
2. В боковой панели нажми **Settings** → раскрой **Advanced UI issue rules**.
3. Name: `Store error banner`, CSS selector: `.notice--error` → **Add rule**.
4. Вернись на вкладку магазина. Счётчик вырос: баннер, который ещё на экране, пойман сразу.
5. Выбери **Standard** и переходи к багу 5: при Express кнопка заказа неактивна.

**Что сломано.** Курьерская служба возвращает цену `null`, и экспресс-доставку выбрать нельзя (`sw.js`, `assets/pages/checkout.js`).

**Почему расширение сначала молчит.** Магазин показывает ошибку своим блоком с классом `notice--error`. У блока нет `role="alert"`, а стандартные правила узнают ошибку именно по таким признакам. Запроса с ошибкой тоже нет: сервер ответил 200. Поэтому следа, который расширение умеет видеть само, просто нет.

**Что ловит расширение после правила.** Видимую ошибку. Карточка: `[Checkout] Delivery unavailable. We couldn't calculate the express…`, со скриншотом.

**Почему это помогает.** В каждом проекте свои баннеры и тосты для ошибок. Одно правило на проект, и расширение ловит их так же, как стандартные. Правило настраивается один раз и сохраняется.

## После прогона

Нажми **Stop and review**: будет 7 карточек (6 без бонуса). Открой **Create ticket** на любой: шаги, факты и скриншот, если он был. **Copy ticket** копирует тикет в Markdown для трекера или ИИ-чата.

Для показа лучше всего подходят четыре карточки:

- **Баг 2.** Шаги приводят к клику в каталоге, хотя пропажу заметили в корзине.
- **Баг 3.** Скриншот того, что мелькнуло на секунду.
- **Баг 5.** На экране «заказ оформлен», а в тикете ответ 500.
- **Баг 6.** В Network зелёный `200 OK`, а в тикете ошибка из ответа.

## Почему не хватает DevTools

- **Нужно держать DevTools открытыми и смотреть в нужную вкладку в нужный момент.** Баг 4 оставляет след только в консоли.
- **В Network запрос не связан с действием.** Ответ 500 по наушникам виден, но проверять ты будешь корзину, а не тот запрос.
- **При переходе на другую страницу Network очищается.** Баг 5 без Preserve log пропадает.
- **Мелькнувший тост в DevTools не сохраняется.**
- **Статус 200 ещё не значит успех.** Баг 6 в Network выглядит зелёным, ошибку видно, только если открыть ответ.

Расширение пишет следы само и складывает их в карточку вместе с шагами.

## Если что-то пошло не так

| Проблема | Что сделать |
| --- | --- |
| Два бага в одной карточке | Между ними прошло меньше 3 секунд на одной странице. Начни заново и выдерживай паузу |
| Лишняя карточка | Опечатка в промокоде или неверный пароль при входе во время записи. Нажми Exclude на карточке |
| Карточки не появляются | Проверь, что идёт запись (Capturing this tab) и что стоит версия 0.3.0 |
| Тост бага 3 не попал в карточку | Скорее всего, стоит старая версия 0.1.0. Поставь 0.3.0 |
| Нет карточки бага 6 | Стоит версия ниже 0.3.0, или в Settings → Capture выключено «Catch errors inside successful JSON responses» |
| Начать заново | В панели **Delete session**, на странице F5 и **Reset demo**, затем снова вход и Start capture |

## Где менять баги

Каждый баг помечен комментарием `PLANTED BUG`: ответы сервера — в [`sw.js`](./sw.js), код страниц — в [`assets/pages/`](./assets/pages/).
